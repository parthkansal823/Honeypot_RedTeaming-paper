# 1 Project Overview

## 1.1 What this project does

This repository answers one question: **can sessions generated by LLM "red-team" agents against a honeypot we own be used to train a classifier for real honeypot traffic?**

It contains everything needed to answer that question from scratch:

- a testbed built on the Cowrie SSH honeypot, with a static shell backend and an LLM-written shell backend;
- a harness that lets an LLM issue one shell command per turn against our own honeypot and records every turn;
- a parser for the public CyberLab honeynet dataset (real attacker sessions);
- shared code that normalises commands from both sources in the same way;
- a label-free comparison of the two corpora;
- tools for blind annotation, agreement measurement and adjudication;
- a four-quadrant transfer experiment;
- scripts that regenerate every table and figure, the paper (Springer LNNS format) and the project report.

## 1.2 Short answer

No, not with a single "explore the system" persona. The synthetic and real sessions are almost perfectly separable (verb Jensen-Shannon divergence 0.700, classifier AUC 1.000). A classifier trained on synthetic sessions reaches a macro-F1 of 0.205 on real sessions, against 0.983 when trained on real sessions, and adding synthetic data to real data gives no gain (0.981). The agents explore files and hunt credentials; most real sessions on the sample day ran one cryptominer dropper.

## 1.5 Safety and ethics

The attacker harness is a research tool for **our own** honeypot only. It connects to exactly one configured host, has no scanning or target-discovery code, and the honeypot holds no real data. The real dataset is public (CC BY 4.0) and uses hashed source identifiers; nothing in this project tries to re-identify anyone. API keys are read from environment variables and are never written to logs or to the repository.
